First public release of TLC.

TLC records recognition — who showed up for whom — in a log that cannot be quietly rewritten. It
never holds, moves or escrows money, and there is no wallet, no balance and no payment rail anywhere in it.

### In this build

- **The activation flow.** Get details, bring back proof, receive an attestation, reach a receipt —
  every step decided by the rules the tests cover, with no second copy of them in the screen.
- **Tamper-evident history.** Every ledger entry is chained to the one before it by SHA-256; edit one
  past entry and verification fails. The `ledger-verify` CLI proves the same property outside the app.
- **Offline first.** No networking code at all in this release, so the APK does not request the
  `INTERNET` permission. It works with the radio off.
- **Honest tokens.** Recognition tokens are signals of appreciation: not currency, not
  transferable, not redeemable, not crypto.

### What this build does not do yet

This is a preview: the flow uses demonstration data and the ledger lives in memory for the length of
a session. Records are not yet kept between launches, there is no account and no sync. On-device
persistence and the two-steward flow are the next milestone.

### Proven by the build, not by the README

- 56 invariant tests across the domain state machine and the hash-chained ledger.
- The `foss` channel is checked for Play Services, Firebase and tracking dependencies.
- The release APK is checked for the absence of the `INTERNET` permission and of Play Services
  classes in its dex, and its signing certificate is pinned to the project's key.

### Early software

This is a foundation, not a finished product. The rules and the ledger are enforced by tests; the
Compose shell is deliberately thin. Features arrive as they can be proven, not as they can be
promised.

GPL-3.0-or-later. No analytics, no advertising identifier, no third-party tracking.
